## 一、问题清单（均已实证，附根因与证据）

### BUG-A：告知书"查看"功能链路断裂（严重）

**现象**：家属端订单详情页点"生成告知书"提示成功，但点"查看告知书"打开的页面加载失败。

**根因（已定位）**：`AiServiceImpl.llmGen()` 的 LLM 调用失败时走 `degraded(type, bizId)` 降级方法，该方法**只 new 了一个 ContentVO 返回，未落库**，导致响应 `data.id = null`。前端 `OrderDetail.vue` 中 `noticeId.value = res.data.id || res.data` 取不到 id 时把整个对象当 id 拼路由，跳转到 `/family/notice/[object Object]`，随后 `GET /api/ai/content/[object Object]` 必然失败。

**实证**：2026-10-29 实测 `POST /api/ai/notice/generate {"orderId":1}`，HTTP 200，响应体：
```json
{"code":200,"data":{"contentType":"NOTICE","content":"AI服务暂不可用...","reviewStatus":"UNREVIEWED",...}}
```
响应中**无 id 字段**（id 为 null 被全局 non_null 序列化省略）。

### BUG-B：AI 功能整体不可用（严重）

**现象**：系统名为"AI赋能"，但告知书、医嘱解读、OCR 三个 AI 功能实际全部走降级/失败。

**根因（已定位）**：`application.yml` 配置 AI 服务地址为 `http://localhost:9001/ocr`（OCR）与 `http://localhost:9002/llm`（LLM），但**项目交付物中从未包含这个 AI 服务（或 mock）的任何实现与启动方式**，9001/9002 端口无任何进程监听。后端日志实证：
```
Caused by: java.net.ConnectException: Connection refused: getsockopt
  at com.example.escort.common.AiHttpClient.llmPost(AiHttpClient.java:29)
  at com.example.escort.module.ai.service.impl.AiServiceImpl.llmGen(AiServiceImpl.java:167)
```
即：熔断、重试、降级等工程化设计都在，但"AI 服务"本身缺失，设计永远跑不到成功路径。

### BUG-C：告知书 prompt 拼接出现 "null"（一般）

`AiServiceImpl.generateNotice()` 第 143-145 行，老人档案 `allergyHistory` 为 null 时直接拼进 prompt，生成内容中出现"过敏史：null"字样。`mobility` 同理可能为空串。

### BUG-D：前端生成告知书后跳转缺防御（一般）

`frontend/src/views/family/OrderDetail.vue`：`noticeId.value = res.data.id || res.data`，当 id 缺失时应提示"生成失败/降级中"并禁止跳转，而不是拼接坏路由。

## 二、修复要求

### R1：交付可运行的模拟 AI 服务（对应 BUG-B）

在项目内新增 `mock-ai-server/`（零依赖 Node 脚本即可，执行环境已有 Node v22；也可自选等价方案），要求：

- 监听两个端口，与 `application.yml` 默认配置一致：
  - `POST http://localhost:9001/ocr/recognize`，请求体 `{"imageUrl":"..."}`，响应 JSON 必须含 `result` 字段（结构化识别结果对象）与 `confidence` 字段（数值，≥0.85 与 <0.85 的场景都要可演示，可通过请求参数或随机/轮换策略实现）
  - `POST http://localhost:9002/llm/chat`，请求体 `{"prompt":"..."}`，**响应体直接为内容文本**（后端将响应 body 原样作为生成内容落库），Content-Type 必须带 `charset=utf-8`
- LLM 返回内容要求：中文、按 prompt 类型区分（含"告知书"→诊前告知书；含"解读"→医嘱通俗解读），并与 prompt 中的字段（科室、预约时间、行动能力、过敏史/诊断、用药建议）呼应；内容为简单 HTML 片段（`<p>`/`<h3>`，前端用 v-html 渲染）
- 所有医疗文案必须为通用就诊常识性提示，禁止出现真实医疗机构名称，禁止给出具体诊疗建议
- 附启动方式说明（写入 HANDOFF.md）：`node mock-ai-server/server.js`

### R2：降级路径必须落库（对应 BUG-A）

`degraded()` 降级内容同样 insert 到 `ai_generated_content` 表（reviewStatus=UNREVIEWED），返回带真实 id 的 ContentVO。保证：即使 AI 服务不可用，"生成→查看"链路也不断裂，查看页展示降级提示文案。

### R3：prompt 空值处理（对应 BUG-C）

`generateNotice` / `generateExplain` 中所有可能为 null 的字段转换为中文默认文案（如"无""未知"），禁止把 "null" 字符串拼进 prompt。

### R4：前端跳转防御（对应 BUG-D）

生成告知书/解读后，校验返回 `data.id` 为有效数值才允许跳转查看页；否则提示"内容生成中或已降级，请稍后从列表查看"（或等价中文提示）。

### R5：同步更新 HANDOFF.md

补充 mock AI 服务的启动步骤与端口说明，保证新模型/新环境按文档可完整跑起系统（后端 + 前端 + mock AI 三个进程）。
