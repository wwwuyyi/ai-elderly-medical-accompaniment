## 五、完整业务流程演示（约 10 分钟）

### 第 1 步：管理员审核陪诊师（管理端标签页）

1. 点击"资质审核"（或首页快捷入口）
2. 找到"王芳"（13800003333），状态为"待审核"
3. 点击行 → 弹窗查看详情（身份证号明文可核对）
4. 点击"通过" → 审核完成

> 备注：13800002222 已预置为已审核状态，可直接跳过审核演示接单。

### 第 2 步：家属下单（家属端标签页）

1. 点击"立即下单"
2. 选择老人"张大爷" → 下一步
3. 选择医院、科室、服务类型（基础陪诊 ¥50/h 或 陪同检查 ¥80/h）、预约时间、服务时长
4. 点击"费用试算" → 确认预估金额
5. 下一步 → 确认下单
6. 订单列表可见新订单，状态为"待派单"

### 第 3 步：管理员派单（管理端标签页）

1. 点击"订单管理"
2. 找到家属刚下的订单（状态=待派单）
3. 点击"派单" → 输入陪诊师 ID（输入 `3`，对应 13800002222）
4. 派单成功 → 订单状态变为"已派单"

### 第 4 步：陪诊师接单+执行（陪诊师端标签页）

1. 点击"接单大厅"
2. 看到派给自己的订单 → 点击"接单"
3. 进入"我的订单" → 点击"开始服务"
4. 模拟服务完成 → 点击"结束服务"

### 第 5 步：管理员结算（管理端标签页）

1. 订单管理 → 找到状态为"服务完成"的订单
2. 点击"结算" → 确认结算
3. 系统自动计算平台抽成（20%），生成结算记录

### 第 6 步：家属评价（家属端标签页）

1. 我的订单 → 找到状态为"已结算"的订单
2. 点击"评价" → 选择星级（1-5）→ 填写评价内容 → 提交
3. 订单状态变为"已完成"

### 第 7 步：AI 功能演示（家属端标签页）

**前提**：Mock AI Server 必须已启动（终端 1）

1. 订单详情页 → 点击"生成告知书"
2. 提示成功后点击"查看告知书" → 展示 AI 生成的诊前告知书（含免责声明）
3. 就医档案 → 选择档案 → 点击"生成医嘱解读" → 展示通俗化解读

### 第 8 步：OCR 演示（陪诊师端标签页）

1. 在服务中的订单 → 上传就医单据图片
2. 点击"发起 OCR 识别" → 等待识别完成
3. 进入 OCR 确认工作台 → 识别结果与原始图片左右对照
4. 可逐字段修正 → 确认入库

> 备注：Mock OCR 交替返回高置信度（0.95）和低置信度（0.72），可演示"待人工确认"场景。

## 六、关键 API 端点速查

| 模块 | 端点示例 | 说明 |
|---|---|---|
| 验证码 | GET `/api/auth/captcha` | 返回 4 位数字验证码图片 Base64 |
| 登录 | POST `/api/auth/login` | 含 role 字段，后端校验端角色一致性 |
| 试算 | POST `/api/order/estimate` | BASIC×2h=¥100.00 |
| 下单 | POST `/api/order` | 日期格式 `yyyy-MM-dd HH:mm:ss` |
| 派单 | POST `/api/order/{id}/dispatch?escortId=3` | 查询参数传 escortId |
| 告知书 | POST `/api/ai/notice/generate` | 依赖 Mock AI :9002 |
| 医嘱解读 | POST `/api/ai/explain/generate` | 依赖 Mock AI :9002 |
| OCR | POST `/api/ai/ocr/recognize` | 异步返回 taskId，前端轮询 |
| 审核详情 | GET `/api/admin/escort/audit/{id}/detail` | idCard 解密为 18 位明文 |

## 九、常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 登录提示"验证码错误" | 验证码图片模糊看不清 | 点击图片刷新，4 位字母数字不区分大小写 |
| 登录提示"该账号不是XX端账号" | 角色选错了 | 切换到正确的角色 Tab 重新登录 |
| 告知书/解读提示"系统异常" | Mock AI 未启动 | 终端 1 执行 `node mock-ai-server/server.js` |
| 下单 500 | 日期格式错误 | 使用 yyyy-MM-dd HH:mm:ss 格式 |
| 端口 8080 占用 | 上次后端未关闭 | `netstat -ano \| grep 8080` 找到 PID 后 kill |
| 三标签页登录互相干扰 | 使用了同一浏览器窗口的新标签 | 确认所有标签页都是同一浏览器的新标签（非 Ctrl+N 新窗口），sessionStorage 天然隔离 |
